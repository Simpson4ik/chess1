# Принципи програмування у проєкті Chess

У цьому проєкті дотримано низки фундаментальних принципів об'єктно-орієнтованого проектування (SOLID, DRY) та базових принципів ООП. 

## 1. Single Responsibility Principle (Принцип єдиної відповідальності)
Кожен клас у проєкті відповідає лише за одну конкретну частину функціоналу і має лише одну причину для змін.

* **Підрахунок фігур:** Клас `Counting` відповідає виключно за підрахунок кількості фігур різних кольорів та типів на дошці. Він нічого не знає про логіку самої гри. 
  [Дивитись реалізацію класу](./ChessLogic/Counting.cs#L9-L46).
* **Відтворення звуку:** Клас `SoundManager` у модулі інтерфейсу відповідає лише за завантаження та відтворення звукових ефектів. 
  [Дивитись реалізацію](./ChessUI/SoundManager.cs#L7-L38).

## 2. Open/Closed Principle (Принцип відкритості/закритості)
Програмні сутності повинні бути відкриті для розширення, але закриті для модифікації.

* **Система ходів:** [Базовий абстрактний клас Move](./ChessLogic/Moves/Move.cs#L9-L21) визначає загальний контракт для будь-якого ходу. Коли виникла потреба додати специфічний хід , я не змінював існуючий код, а розширили його, створивши [новий клас Castle](./ChessLogic/Moves/Castle.cs#L9-L63), який успадковує `Move`.

## 3. Don't Repeat Yourself (DRY - Не повторюйся)
Уникнення дублювання коду шляхом винесення спільної логіки в базові класи.

* **Логіка ковзання фігур:** Слон, Тура та Ферзь мають схожу механіку руху. Замість дублювання циклів перевірки, спільна логіка винесена у захищені [методи MovePositionInDir та MovePositionInDirs](./ChessLogic/Pieces/Piece.cs#L16-L35) базового класу `Piece`. 
* Дочірні класи, такі як `Bishop`, просто [викликають цей метод](./ChessLogic/Pieces/Bishop.cs#L28-L31), передаючи свої напрямки.

## 4. Encapsulation (Інкапсуляція)
Приховування внутрішнього стану об'єкта та надання доступу до нього лише через публічні методи або властивості.

* **Захист стану дошки:** Внутрішнє представлення шахівниці - це двовимірний масив фігур `pieces`. Він прихований, а безпечний доступ для читання та запису надається через [публічні індексатори](./ChessLogic/Board.cs#L10-L20).

## 5. Polymorphism (Поліморфізм)
Здатність об'єктів різних класів реагувати на однакові виклики методів по-різному.

* **Отримання ходів:** Базовий клас має [абстрактний метод GetMoves()](./ChessLogic/Pieces/Piece.cs#L14). Клас `GameState` при генерації ходів просто [викликає piece.GetMoves(...)](./ChessLogic/GameState.cs#L78-L82) для кожної фігури. Завдяки поліморфізму, для різних фігур автоматично виконується їхня специфічна логіка, хоча код працює з абстрактним типом `Piece`.
